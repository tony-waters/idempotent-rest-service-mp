Architecture

Adding Idempotency

rest-service writes an order and relays it to email-service without a direct call and without the producer ever writing to a broker. This page traces that path end-to-end — the request, the transactional write, the CDC relay, the idempotency check, and the trace that survives all of it — and then shows how it's actually scheduled across a Kind cluster.

  • Spring Boot
  • Postgres · logical WAL
  • Debezium / Kafka Connect
  • Strimzi Kafka · 3 brokers
  • Redis
  • Kind + kubectl

Request & event flow

One HTTP request produces one transaction. Everything after that — the Kafka message, the email, the trace — is a side effect CDC discovers later, not a call rest-service makes directly.

primary request path idempotency check (Redis) async CDC relay (Kafka) trace propagation carried value, not a call

Components

What each piece in the diagram above actually is.

rest-service

Spring Boot · 2 replicas · NodePort 30081

Writes the Order and Outbox row in one transaction; owns the Idempotency-Key check against Redis.

Postgres

StatefulSet · single instance

wal_level=logical for Debezium. Holds Order and Outbox — the Outbox table has no reader but the CDC connector.

Redis

Deployment · single instance · no persistence

Caches Idempotency-Key → orderId. Losing it on restart just reopens the dedup window.

Kafka Connect + Debezium

KafkaConnect · single instance

Tails the Postgres WAL via pgoutput and republishes each Outbox row with the Outbox Event Router SMT.

Kafka

Strimzi · 3 dual-role broker/controller pods

Replication factor 3, one broker per worker node. Single topic: outbox.event.order.

email-service

Spring Boot · 2 replicas · NodePort 30082

Consumes the topic and logs a confirmation, throttled by a blocking resilience4j rate limiter — lag growth under load is the intended effect.

Tempo

single binary · local storage

Receives OTLP spans from both services and derives Grafana's service graph.

Prometheus + Grafana

Prometheus Operator · NodePort 30390 / 30300

Scrapes broker, Connect, and app metrics. Grafana ships two pre-provisioned dashboards.

kafka-ui

single instance · NodePort 30080

Browse topics, consumer lag, and connector status.

Deployment topology

Built on Kind: 1 control-plane + 3 worker nodes. Pod anti-affinity is declared for exactly three things — rest-service, email-service, and the Kafka broker pool — everything else is a single instance the scheduler places freely.

app pod · anti-affinity constrained Kafka broker pod · anti-affinity constrained single instance · scheduler's choice
